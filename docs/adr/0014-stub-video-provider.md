# ADR-0014: ローカルのスタブ動画 Provider を一級の実装として持つ

Status: Accepted
Date: 2026-09-16
Decider: Architect

## Context

Phase 1 の縦串（Project → Music → Shot → Generate → Take → Timeline → MP4）を通したい。
しかし現時点で **fal.ai のアカウントはあるがクレジットが無い**（2026-09-16 時点）。

さらに、仮にクレジットがあっても次の問題が残る。

- **縦串のテストを回すたびに課金される。** 1 回の生成が数十円でも、開発中に何十回も回せば無視できない。
- **CI で実行できない。** 外部 API を CI から叩かない方針（ADR-0004 の契約テスト）と矛盾する。
- **生成は数十秒〜数分かかる。** 反復速度が落ちる。
- **非決定的。** 同じ入力で違う映像が出るため、タイムラインやレンダリングの回帰テストに使えない。

縦串で検証したいのは「**配線が正しいか**」であって「映像が綺麗か」ではない。
Shot → Spec → Job → Take → MediaAsset → Timeline → Render の経路が通ることが目的である。

## Decision

**`VideoProvider` のローカル実装 `stub` を作り、Phase 1 の既定にする。**

一時的なモックではなく、**恒久的に維持する一級の Provider 実装**として扱う。

```
packages/providers/video/
  ├─ stub.ts        ← FFmpeg でプレースホルダ動画を生成する（既定）
  ├─ fal-seedance.ts
  └─ byteplus-seedance.ts   ← Phase 6 前
```

### スタブの挙動

FFmpeg で、**Shot の内容が目で分かる**プレースホルダ動画を生成する。

- 背景色は `shotId` のハッシュから決定的に決める（Shot ごとに違う色 = 切り替わりが目で分かる）
- 画面に `code` / `description` の冒頭 / `camera.size` / 生成尺 / `specHash` の先頭 8 文字を焼き込む
- フレーム番号とタイムコードを表示する（**音ズレとフレーム落ちが目視で分かる**）
- 指定された尺・解像度・fps・アスペクト比を**正確に**守る
- `seed` から決まるノイズを少し乗せ、Take ごとに違う絵にする（Take 切り替えの確認用）

### capability 記述

スタブも他の Provider と同じ `VideoModelDescriptor` を持つ。
**あえて実モデルに似た制約を宣言する**こと。

```ts
durations: { mode: 'enum', values: [4, 6, 8] }   // Veo を模した離散値
referenceImages: { max: 3, roles: [...] }        // Veo / Runway を模した枚数制限
seed: true
cameraControl: 'prompt'
```

理由: **尺の量子化（ADR-0011）と参照の切り詰め（§8）が実際に効くことを、
クレジット無しで検証できるようにするため。** 制約の緩いスタブだと、
本番 Provider に切り替えた瞬間にこれらのロジックが初めて走ることになる。

### 何を検証できて、何を検証できないか

**検証できる（スタブで十分）**
- Shot → ShotGenerationSpec の組み立てと specHash の安定性
- ModelRouter のハードフィルタとスコアリング
- 尺の量子化、参照の優先度つき切り詰め
- ジョブのキューイング、ポーリング、失敗時のリトライ
- MediaAsset への取り込み（probe / proxy / サムネ / ポスターフレーム）
- Take の作成と選択、Timeline への反映
- レンダリング（尺・音ズレ・トランジション）
- コスト集計と予算ガードの配線（スタブのコストは 0）

**検証できない（実 Provider が要る）**
- capability 記述が実 API と合っているか（**リスク R12 のまま残る**）
- 実際の生成時間とコスト
- 参照画像がキャラクター一貫性に効くか
- 期限付き URL のダウンロード処理

## Consequences

+ **クレジット無しで Phase 1 の縦串を完走できる。**
+ 縦串の E2E テストを CI で回せる。課金もレート制限も無い。
+ 決定的なので、タイムラインとレンダリングの回帰テストに使える。
+ 実 Provider が落ちているときも開発を止めずに済む（恒久的に価値がある）。
+ Provider 抽象化が「HTTP・CLI・ローカル」の 3 形態に耐えることを検証できる。
− スタブの capability 記述を手で維持する必要がある。
− **実 API との乖離は残る。** 下記の通り、少額でよいので一度は実機確認すること。

## Follow-up

- [ ] **クレジットを入れたら、まず 1 Shot × 1 Take だけ実 API で生成する。**
      5 秒 × $0.303 = **約 $1.5**。これで capability 記述を実測値に直し、R12 を潰す。
      全 MV の生成（約 $180）に進む前に必ずやること。
- [ ] 代替案として **Replicate は $10 の無料クレジットをカード無しで付与**するとの情報がある。
      fal.ai にクレジットを入れる前に、こちらで capability の実測を済ませる選択肢もある。
- [ ] 実 Provider が使えるようになっても **スタブは消さない**。既定を切り替えるだけにする。
