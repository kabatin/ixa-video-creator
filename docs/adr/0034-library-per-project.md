# ADR-0034: キャラクター・ロケーション・ブランド資産をプロジェクトごとにする

- Status: Accepted
- Date: 2026-10-03

## Context

制作者 2026-10-03「楽曲以外のキャラクター、ロケーション、ブランド資産が全プロジェクトで共有になっている。
プロジェクト単位にしないと大変なことになる」。

ワークスペースに 1 組で、どのプロジェクトを開いても同じ一覧が出ていた（iXA の素材ツリーに LUNA BREW のロゴが並び、
iXA の映像を LUNA BREW の色でもブランド点検していた）。楽曲だけは最初からプロジェクトごとだった。
直したいのに別の作品のキャラクターまで変わる、という事故も起きうる。

## Decision

- **キャラクター（Look・識別画像・Look の画像を含む）・ロケーション・ブランド資産はプロジェクトごと。** `project_id` を持つ
  - `workspace_id` は残す。画像のアップロードと素材ファイル（MediaAsset）はワークスペース単位のままで、そこが読む
  - 一覧と作成は `/projects/{projectId}/characters`・`…/locations`・`…/brand-assets`。ワークスペースで引く口は消した
  - Shot に付けられるのは同じプロジェクトのものだけ（割り当て・ロケーション 1 件ずつ／まとめて・AI の手伝いで 422）
  - ブランドの色の点検（Brand Review）はそのプロジェクトの色だけを見る
- **別のプロジェクトで使うときは複製する**（`POST /projects/{projectId}/library-imports`、素材ツリーの「ほかのプロジェクトから取り込む…」）
  - キャラクターは Look・識別画像・Look の画像・正面の絵ごと。画像のファイルは複製せず同じ MediaAsset を指す
  - 複製した後は別物。片方を直しても、もう片方は変わらない
  - 同じワークスペースのものだけ。書く前に全部を確かめ、1 件でも取り込めなければ何も作らない
- 既存のデータはマイグレーション 0021 で振り分けた: 使っている Shot が最も多い生きたプロジェクト、無ければワークスペースで
  最も古い生きたプロジェクト。人が直したい分は取り込み（複製）と削除で直す
- ワークスペース全体を並べていたサイトの一覧（キャラクター・素材ライブラリ）はたたみ、プロジェクトへの案内にした。
  キャラクターの詳しい編集画面（`/characters/{id}`）は残し、インスペクターから行く

## Consequences

+ 作品ごとに素材が分かれ、別の作品を直しても互いに影響しない
+ ブランドの点検が作品の色だけを見る
− 同じキャラクターを複数の作品で使うと、直すときは作品ごとに直す（共有したい場合の仕組みは無い。要るならあとで）
− モーションテンプレートはワークスペース単位のまま（まだ画面にも API にも出ていない）
