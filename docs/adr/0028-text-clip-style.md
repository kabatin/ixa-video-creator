# ADR-0028: テロップの見た目・位置・フェードと、スタイルの保存・一括適用

Status: Accepted
Date: 2026-09-28
Decider: Claude（Architect）。制作者の選択（2026-09-28「一般的な動画編集ツールと同等の機能を」→ 見た目・位置・フェード＋スタイルの保存と一括適用から、の提案を受け入れ）

## Context

テロップで決められるのは「文字」と「型 2 種（中央 / 下帯）」だけだった。大きさは文字数から自動、
色は白・太字・書体 1 種で固定、フェードも無い。一番困るのは、MV の歌詞（数十行）に同じ見た目を
まとめて当てられないこと。

調べて分かった前提:
- テロップの中身は `content.params`（自由な record）。形の正は `TextClipParams`（domain）
- タイムラインの小窓で文字を直すと、`params` が `{ text }` で丸ごと置き換わっていた
  （足した値が次の編集で消える）
- 外部フォントは読まない方針（プレビューと書き出しでフォントの有無が食い違わないよう）

## Decision

### 見た目は各テロップの `params.style` に持つ

- 項目: 書体（ゴシック / 明朝 / 丸ゴシック）・大きさ（画面の高さに対する割合、null は自動）・太さ・色・
  縁取り（色と太さ）・影（なし / 弱 / 強）・背景の帯（色と濃さ）・揃え・定位置（9 か所）・
  ずらし（画面の幅・高さに対する割合）・フェードイン / アウト（2 秒まで）
- **型の既定値に `style` を重ねる**（`resolveTextStyle`）。既定値は今の見た目と同じなので、
  `style` の無いテロップは同じ絵になる。`null` は「無し」の指定（下帯の背景を消すなど）
- 単位は割合。画面に px は出さない（大きさは「画面の高さの %」）
- `style` は項目ごとに読む。読めない見た目は捨てて既定の見た目で描き、検査で知らせる
  （`text_style_unreadable`）。保存の API は読めない見た目を 422 で弾く
- 書体は端末に入っている和文書体のまとまりで指定する（外部フォントは読まない）

### スタイルはプロジェクトごとに名前を付けて保存する（`text_styles`）

- **当てると値を写す。** テロップ側に見た目と `styleId`（どのスタイルから当てたか）が残る。
  描くときにスタイルを引きに行かないので、タイムライン文書・書き出しの記録はそのまま
- スタイルを直したら「使っているテロップ N 件にも反映」を選べる（`styleId` で探して当て直す）
- まとめて当てる口 `POST /projects/{id}/clips/text-style`。文字には触らない。1 件でも
  テロップ以外・別の Project のクリップが混じれば何も変えずに 422

### 画面

- インスペクターに「テロップ」を足す。タイムラインの小窓に「見た目を編集」
- 欄は確定ごとに自動保存。色はピッカーを閉じた時点で保存する（動かしている間は書かない）
- 小窓で文字を直しても見た目とスタイルを残す
- タイムラインの帯には型の名前ではなく文字そのものを出す

## やらないこと（今回）

- スライド・1 文字ずつなどの動き（保留中のタイトル演出と一緒に）
- プレビューの上でドラッグして動かす（位置は 9 か所＋ずらしの数値）
- フォントのアップロード・Web フォント。Windows で見ると丸ゴシックがゴシックになるなど、
  端末による見え方の差は残る
- 一括変更の取り消し履歴（今は Shot だけの仕組み）

## Consequences

- MV の歌詞 28 行に、元の MV に寄せたスタイル「歌詞」（明朝・普通の太さ・#FFF8EE・強い影・
  下寄せ中央・フェード 0.5 秒）を画面から作って一括で当てられた
- 下帯の左の線は帯の飾りとして扱い、帯を消したら線も引かない
