# ADR-0029: 絵コンテの画像（Shot の最初のフレーム）を Codex CLI で作る

Status: Accepted
Date: 2026-09-28
Decider: Claude（Architect）。制作者の判断（2026-09-28「Codex CLI は課金しているので普通に使える。繋ぎこんでもいい」）

## Context

本来の流れ（曲 → 分割 → Shot → **絵コンテの画像** → プロンプト → 動画生成 → テロップ・トランジション → 書き出し）のうち、
アプリに無いのは絵コンテの画像を作る工程だけだった。

- 絵の置き場はある。Shot の「最初のフレーム」＝ 手で付けた `start_frame` の参照 1 件（ADR-0025）。
  無料の `local/still-motion` はこれを動かして Take にする
- `@ixa/provider-image` の Codex CLI 実装は骨組みだけで、`codex exec` で画像生成を無人で回せるかが未確認だった（ADR-0012 の宿題）
- ADR-0012 は「Shot ごとのキーフレーム（100 枚以上・自動ループ）は HTTP の画像 Provider」としていた

## 実測（spike、codex-cli 0.154.0）

- `codex exec --skip-git-repo-check --ephemeral --sandbox workspace-write -C <作業ディレクトリ> --json -i <参照>…` で無人で完走する。
  1 枚 60〜76 秒
- **指示は stdin で渡す。** `-i` は複数の値を取るので、後ろに置いた指示を画像として食う（`No prompt provided via stdin` で終了コード 1）。
  stdin は必ず閉じる（開いていると入力の終わりを待ち続ける）
- 画像は `$CODEX_HOME/generated_images/<thread_id>/exec-*.png` にでき、指示すれば作業ディレクトリへ写す。
  `thread_id` は `--json` の最初の出来事 `thread.started` に出る
- 大きさは横長 1536×1024 / 縦長 1024×1536 / 正方形 1024×1024 の 3 つだけ
- 参照画像はよく効く（同じガレージ・ランプ・ヘルメットを保った）

## Decision

### 絵は最初のフレームに入れる

作った絵は PNG の素材（出どころ `generated_image`）として取り込み、**最初のフレームを差し替える**。
差し替えの規則は API（手で付ける）と worker が同じ 1 箇所（`@ixa/generation` の `replaceManualStartFrame`）を使う。
ストーリーボードの絵は、採用 Take が無い Shot では最初のフレームを使う（今までは Take のサムネイルしか見ず、絵が出なかった）。

### ジョブは追記のみ（`image_generation_jobs`）

1 件のジョブで 1 枚。状態・Provider・参照に使った素材・できた絵・失敗の理由・再現用の記録（CLI の版・終了コード・thread_id。
**指示の本文は入れない**）を残す。作り直しても前の絵と記録は残る。

### 中身の説明は動画と同じ組み立て

`compileStartFramePrompt` は `compileSpec` を使い回す（Shot の説明・人物・衣装・画角・mood・スタイル指示）。
静止画なのでカメラの動きだけ外す。Codex 固有の手順（画像生成ツールで 1 枚・形・参照の意味・保存先）は Provider が足す。
参照は登場人物・衣装・場所・スタイル・ブランドから最大 4 枚（最初のフレームと前のカットの最後の 1 コマは渡さない）。

### 形はモデルが作れる中から選び、比に切り抜く

プロジェクトの比と同じ向きでいちばん大きい形で作り、worker が中央で切り抜く（16:9 なら 1536×864）。
主題が端に寄らないよう指示でも伝える。

### 動かし方

- worker の新しいキュー `image`、**同時 1 本**（Codex は契約の利用枠で動き、1 枚 1 分ほど）
- API は頼むだけ（202）。1 件（作っている間は 409）とまとめて（100 件まで、既定は絵の無い Shot だけ）。
  キューに入れ損ねたらジョブを失敗にする（待っているまま残すと二度と頼めない）
- 出来事 `image_job.status` で画面が絵を取り直す。失敗は理由をそのまま出す
- どの口で作るかは `IMAGE_PROVIDER=stub|codex_cli`（既定 stub）。**切り替えは `.env` に書く**
  （turbo は宣言していない環境変数をタスクへ渡さないので、シェルで export しても届かない）
- 取り込んだら、Codex の作業ディレクトリと CODEX_HOME のその回の絵を消す

### ADR-0012 の改め

「Shot ごとのキーフレームは HTTP の画像 Provider」を改め、**人が見て選ぶ数十枚の規模なら Codex CLI で作る**。
数百枚を自動で回す用途（Codex の利用枠と所要時間では足りない）には、引き続き HTTP の画像 Provider を足す。

## やらないこと（今回）

- 前の絵の一覧から選び直す画面（記録は残るので後で足せる）
- 費用の画面への計上（Codex は契約の利用枠で、1 枚あたりの実費が取れない）
- マスク編集・四面図（ADR-0012 の本来の用途）
- 動いている Codex を途中で止める口（時間切れ 5 分で必ず終わる）

## Consequences

- 新しい Project で 3 Shot（うち 1 つにライダーの四面図を当てた）を実機で作り、3 枚とも 1 分ほどで 16:9 の絵になった。
  参照を当てた Shot にはライダーの特徴が出た
- Shot の一覧は、生成ジョブ以外の出来事をすべて Shot の状態として当てていた（絵のジョブの running が Shot に書き込まれるところだった）。
  Shot の状態として当てるのは `shot.status` だけにした
