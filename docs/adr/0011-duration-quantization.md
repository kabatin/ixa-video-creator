# ADR-0011: 生成尺は切り上げ、編集尺はトリムで作る

Status: Accepted
Date: 2026-09-16
Decider: Architect

## Context

Provider API 調査で、**動画生成モデルの多くが任意の秒数を出せない**ことが判明した。

| モデル | 指定できる尺 |
|---|---|
| Google Veo 3 / 3.1 | **4 / 6 / 8 秒のみ**（1080p・4K・参照画像使用時は 8 秒固定） |
| Kling | **5 秒 または 10 秒のみ** |
| Seedance 2.0 | 4〜15 秒（連続値） |
| Runway Gen-4 系 | 2〜15 秒（モデル依存） |

一方、本システムは Shot の尺を**ビートにスナップ**する（例: BPM 128 で 2 小節 = 3.75 秒）。
ビートに乗った尺とモデルが出せる尺は、原理的にほぼ一致しない。

これを放置すると、「ビートに合わせると生成できない」「生成できる尺にするとビートがズレる」
のどちらかになり、Music Video として成立しない。

## Decision

**生成尺と編集尺を分離する。**

```
生成尺 (generationDurationSec)
  = モデルが出せる値のうち、編集尺以上で最小のもの（切り上げ）
  例: 編集尺 3.75 秒 → Veo なら 4 秒、Kling なら 5 秒

編集尺 (Shot.durationSec)
  = ビートにスナップした、タイムライン上の実際の尺
  生成された素材を sourceInSec からトリムして使う
```

Shot に **`sourceInSec`**（採用 Take のメディア内の開始オフセット）を追加する。

```ts
type Shot = {
  // ...
  startSec: Seconds        // タイムライン上の位置
  durationSec: Seconds     // 編集尺（ビートスナップ済み）
  sourceInSec: Seconds     // 採用 Take のメディア内の開始位置（既定 0）
}
```

- `ShotGenerationSpec.durationSec` には**生成尺**（切り上げ後）を入れる。
- 切り上げは `packages/domain/generation/duration.ts` の純粋関数
  `quantizeDuration(requested, capabilities)` が行う。Model Router のハードフィルタもこれを使う。
- 生成尺が編集尺を超える分は「のりしろ」として残す。
  これは**意図的な余白**であり、以下に使える。
  - トランジション（クロスディゾルブ）のための重なり
  - 編集時の微調整（イン点を 0.2 秒ずらす、など）
  - モデルが冒頭・末尾に出しがちな不安定フレームの回避

### 既定のトリム位置

生成尺 > 編集尺のとき、`sourceInSec` の既定値は **0 ではなく中央寄せ**とする。

```
sourceInSec = min(0.15, (生成尺 - 編集尺) / 2)
```

理由: 動画生成モデルは**冒頭 0.1〜0.3 秒が不安定**（被写体が定まらない、
モーションが立ち上がっていない）になりやすい。先頭を少し捨てる方が歩留まりが良い。
ただし start_frame を指定した場合は冒頭が最も安定するため、その場合は `sourceInSec = 0` とする。

## Consequences

+ ビートスナップと Provider 制約が両立する。
+ トランジション用の素材が自然に確保される。
+ モデルを切り替えても編集尺が変わらない（タイムラインが壊れない）。
− 使わないフレームの分だけ生成コストを払う。
  例: 編集尺 3.75 秒を Kling（5 秒固定）で作ると 25% が無駄になる。
  → Model Router のコスト計算は**生成尺ベース**で行う。無駄も含めて正しく見積もる。
  → ビートスナップ時に「このモデルなら 4.0 秒がちょうど」といった提案を UI で出す余地を残す。
− Shot に状態が 1 つ増える。
  → `sourceInSec` は Take を差し替えても維持する（Take swap で編集が壊れないため）。
