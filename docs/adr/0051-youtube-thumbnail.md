# ADR-0051: YouTube のサムネイルを書き出す（Thumbnail コンポジションとキーアート）

Status: Accepted
Date: 2026-10-17
Decider: Claude（Architect）

## 背景

制作者は仕上がった動画を YouTube に上げる。そのたびに **1280×720・2 MB 未満の JPEG** のサムネイルが要る。
いまは書き出した動画から別のアプリでコマを切り出し、文字を載せている。作品の絵と書体はもうアプリの中にあるので、
ここで作れれば手間が消える。顔が大きく、題名が大きく読める 1 枚にしたい。背景は「いまの位置のコマ」「Shot の絵」
「AI に描かせた 1 枚」から選びたい。

アプリの原則は**プレビューがそのまま書き出し**（ADR-0010）。サムネイルも、画面で見た 1 枚と書き出した JPEG が
同じでなければならない。

## 決めたこと

- **`packages/render` に `Thumbnail` コンポジション（1280×720・1 コマ）を足し、Root に登録する。**
  画面の `@remotion/player` と worker の `renderStill` が同じコンポジションを同じ props で描く
  - 背景が `timeline_frame` なら、**既存の `TimelineComposition` をそのまま** `<Freeze>` でそのコマに止めて描く
    （書き写さない）。作品の解像度から 1280×720 を覆う大きさ（cover）にし、その上で拡大（zoom 1〜2）と寄せ（focus 0〜1）をかける
  - 背景が `image` なら `<Img>`。覆い方・拡大・寄せの計算は同じ純粋関数（`thumbnail-layout.ts`）を通す
  - 題名は太く大きく、縁取りと影を付ける。副題は小さく。差し色の帯を 1 本。配置は 3 つ
    （`left`: 左 3 分の 1 に文字・`center`・`bottom`: 下の帯）。どれも顔の上に文字を重ねにくい形にする
  - 書体は既存のテロップと同じ端末の和文書体（`text-style-css.ts`）。外部フォントは読まない
- **仕様は domain の `ThumbnailSpec`（zod）。** 背景・拡大・寄せ・題名（1〜40 字）・副題（60 字まで）・配置・題名の色・差し色・書体。
  API・worker・画面・MCP は同じスキーマを通す
- **書き出しは追記のみの記録 `thumbnails` 表。** 1 回押すごとに 1 行（`queued → rendering → done | failed`）。
  ファイル名（`<作品名> サムネ <YYYY-MM-DD HH.MM.SS>.jpg`）は頼んだときに決めて行に持つ
- **キュー `thumbnail`（同時 1 つ）。** API が行を作ってジョブを積み、worker が `renderStill`（JPEG）で描く。
  **2 MB 以上なら画質を 90 → 80 → 70 と下げて描き直し、それでも超えたら失敗にする**（黙って大きいまま出さない）
- **`timeline_frame` の TimelineDocument は、書き出しの口と同じ `loadTimelineDocument` で API が組み、ジョブの中身（Redis）で渡す。**
  文書には署名付き URL が入っているので **DB の行には書かない**（行には `atSec` だけ）。動画の書き出しは文書を行に持つが、
  サムネイルは文書を後から辿る必要が無い（仕様から描き直せる）ので持たない。署名の期限（1 時間）を過ぎて積み直されたジョブは失敗し、
  もう一度押せば新しい URL で描ける。`image` の背景は worker が描く直前に URL を発行する
- **できた JPEG は素材（MediaAsset、kind `image`）にする。出どころは新しい `thumbnail`**（`rendered` は書き出しジョブを指すので使い回さない）。
  中身が同じ JPEG が既にあれば、それを指す（素材の表は同じ中身を 1 つしか持てない。書き出しと同じ扱い）
- **手元の書き出しフォルダへ入れるのは、動画と同じ口（API の `syncRenderFolder`）。** フォルダを開くときに、まだ入っていない
  サムネイルも入れる。もうあるファイルは上書きしない（`.part` に書いてから名前を変える）。worker はフォルダに書かない（ADR-0036 のまま）
- **画面の状態はポーリングで追う。** 動画の書き出しと同じ（出来事は足さない）。1 枚は数秒で終わる
- **キーアート（AI の背景）は絵のジョブの新しい種類 `key_art`。** Shot にもキャラクターにも属さず、作品にだけ属する。
  自由な指示（500 字まで）を行に持つ。指示文は作品のコンセプト・ルック・避けたいもの・登場人物と、
  「サムネイルの主役の絵。顔を大きく、強いコントラスト、左に大きな題名を置く余白」から組み、人物の識別画像を参照に添える
  （モデルの上限まで）。横長 16:9 で頼んで 16:9 に切り抜き、素材（出どころ `generated_image`）にする。
  状態の知らせは既存の `image_job.status`（`shotId`・`characterId` が null）。止めるのも既存の「絵を止める」
- **MCP に `export_thumbnail`。** キーアートなら候補を 2 枚作って待ち、1 枚目（`candidateIndex` で選べる）で描く。
  候補の素材 ID を全部返すので、エージェントは別の候補でやり直せる。できた JPEG を画像として返し、出来を自分の目で見られるようにする

## 今回の外

- 文字の位置を指でずらす、文字を 3 行以上に組む、ロゴを載せる。3 つの配置で足りるかを使ってから決める
- 外部フォント（Google Fonts など）。書き出し環境ごとに出たり出なかったりする（ADR-0028 と同じ理由）
- YouTube への直接のアップロード。鍵の扱いを決めていない
- サムネイルの行から作り直す口（同じ仕様でもう一度）。画面が前の仕様を読み込んで押し直せば足りる
