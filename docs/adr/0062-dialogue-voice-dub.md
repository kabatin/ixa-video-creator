# ADR-0062: H3 の声を、キャラクターの Gemini の声で読み直して口に合わせて差し替える

Status: Accepted（段 5a・5b）
Date: 2026-10-26
Decider: Claude（Architect）

## 背景

会話劇の計画の段 5。段 1〜4 で、セリフのある Shot は H3 に音付きで頼み（ADR-0059）、Take の音を書き出しまで残し（ADR-0060）、
2 段字幕を出せるようになった（ADR-0061）。H3 の声は口に合っているが、声質がキャラクターごとにそろわない。

AnimalVideo（新 Mac）では、Gemini の声に差し替えて口に合わせる仕組みが実際に動いている。作りと値はそこから聞いた（2026-10-26）。
**コードは写していない**（値と形だけ）。

段 5a は計算と Provider、段 5b はジョブ・DB・API・画面・MCP・字幕。

## 決めたこと（段 5a）

### 1. セリフの行の「差し替えの指定」（`DialogueLine.dub`）

任意の `dub: { style?, placeAtSec?, fitSec?, cutSec?, levelDb?, keepOriginal?, snap?, added?, levelLikeIndex?, startSec?, endSec? }`。

- **strict のまま**足した（知らない欄は今も弾く）。上限つき（時刻 0〜120 秒・長さ 0.1 秒以上・距離 -40〜12 dB・指示 200 字）。
- 1 行の中の食い違いは保存の時点で止める: 収める長さと切る長さの両方／区間の片方だけ・逆さ／足す行に置く時刻が無い／
  足す行で元の声のまま／足す行に行の区間／足す行でないのに `levelLikeIndex`／
  元の声のままの行に置く時刻・収める長さ・切る長さ・読み方の指示。
- 行の並びの中: `levelLikeIndex` は**足す行ではない別の行**を指す（`DialogueLines` の検査）。
- 指定の無い行は鍵ごと無い。前からの行・spec・specHash は 1 バイトも変わらない（spec はセリフの行を欄ごとに写すので、`dub` は spec に入らない）。

### 2. 差し替えた Take の記録（`ProviderParams` の `dub`）

`{ kind: 'dub', sourceTakeId, voiceTool: 'gemini_api', model, integratedLufs, lines: DubLineRecord[] }`。
行ごとに `mode`（lip / place_at / fit / cut / keep_original）・`added`・元の区間・置いた区間（**字幕の時刻の正**）・
一致率・伸縮の幅（最小・最大）・使った読み方・警告（コードと文）。strict・上限つき。
行の中の食い違い（置いた終わり < 始まり、伸縮の最小 > 最大、元の区間の片方だけ、足す行なのに元の区間がある／足す行でないのに無い）は拒む。

### 3. 計算（`@ixa/domain` の `dub/`。純粋）

| 関数 | 値 |
|---|---|
| `speechChunks` | 10ms 刻みの RMS（dB）で、最大 -30 dB より上を声。0.12 秒未満の途切れはつなぎ、0.06 秒未満は捨てる |
| `trimBounds` | 読み上げの頭と尻の -45 dB 未満を落とし、0.15 秒ずつ残す |
| `pairChunks` | 1 対 1 に組む。数が違えば多い方を、すき間の短い所からつなぐ |
| `planLipPair` | 組の中の間を詰め（語頭 0.04・語尾 0.06 秒残す）、倍率 =（詰めた長さ − 0.1）÷ 元の区間。元の区間の頭 -0.04 秒に置き、次の区間に 0.03 秒残して切る。最後の組は Shot の尺で切る |
| `chunkTempo` | 0.8〜1.6。**1.6 を超えたら止める**（AnimalVideo の 1.8 までの詰め込みは使わない）。1.4 超は「早口に聞こえます」の警告。0.8 未満は 0.8 にして警告 |
| `fitTempo` / `cutPlan` | 収める: 長いときだけ 長さ ÷ fitSec（1.6 超は止める）。切る: 縮めずに切り最後 min(0.15, cutSec) 秒でフェード |
| `agreement` | 「話す／黙る」を 10ms ごとに比べた割合。比べる区切りが無ければ null |
| `muteRanges` | 行の [始まり -0.05, 終わり +0.1]、前後 0.3 秒以内の声の区間まで広げる。重なりはまとめる |
| `assignLines` | 足す行を除いた行に区間を割り当てる。手の区間はそのまま使う。**手の区間の行で並びを区切り**、その間のふつうの行には、その間の時刻にある区間だけを割り当てる（手の区間をまたいでつながない。またぐと手の区間に重なる）。読み上げの長さがあれば長さで選ぶ（下の「行の区間を読み上げの長さで決める」）。無ければ行の数につなぐ。足りなければ、どの行かを番号で言う日本語の理由で止める |
| `readingVariants` | 素の文／句読点の後に `<short pause>`／読点を外した文（同じ文になるものは省く）。頭の「……」は読まない。数が合い一致率 0.9 以上で打ち切り、一番高いものを使う（どれも測れなければ最初に試したもの） |
| `voicedLevelDb` | 声のある所（最大 -25 dB より上）の力の平均 |

決めたこと（計画に書いていなかった細部）:

- **1.6 倍を超えたら、口に合わせる行も止める**（計画の冒頭の「1.6 倍を超える行は止めて理由を出す」に従った。丸めて置くと次の区間に重なって切れる）。
  読み方を変えれば収まることがあるので、止めるかどうかは段 5b で 3 通り試した後に決める。
- `snap: false` は「消す範囲を広げない」の意味にした（行の範囲 [-0.05, +0.1] は消す）。`keepOriginal` の行は消さず、
  その行の区間に掛かる声の区間へは、他の行の消す範囲も広げない（残す声を消さない）。
- 一致率は比べる窓を呼ぶ側が決める（`voicedMask(chunks, start, end)`）。Shot 全体で比べると黙っている所が一致率を水増しするので、段 5b は行の消す範囲で比べる。

### 4. 音（`@ixa/media` の `dub/`）

- `rmsFramesFromPcm` / `readRmsFrames`: 16kHz・モノラルの PCM、窓 400・刻み 160（10ms）。音量合わせは窓 1024・刻み 256。
- `stretchChunks`: 切り出してつなぎ（つなぎ目 8ms フェード）、一定の倍率の atempo（0.5〜2.0 を外れたら段を重ねる）。
- `matchLevelGainDb`: 元の H3 の声（行の区間）と同じ大きさ + 距離の dB。どちらかが測れなければ距離だけ。±20 dB に抑える（`voice-audio.ts` と同じ）。響き・EQ は掛けない。
- 大きさを測る音は `-ac 1`（左右の平均）。声（モノラル）は `pan=stereo|c0=c0|c1=c0` で左右に同じ大きさで写す
  （aformat に任せると左右 0.707 倍で写し、合わせた大きさより 3 dB 小さく鳴った。ステレオの元の音で測って直した）。
- `mixDub`: 元の音を 1ms の区切りにして `volume='1-max(clip(…))':eval=frame` で範囲の中だけ 0、範囲の外側 15ms で元へ戻す
  （端でぷつっと鳴らさない）→ 声を `volume`・`adelay` →
  `amix normalize=0 duration=first` → loudnorm 2 パス（-16・TP -1.5・LRA 11・linear）→ 映像は copy・AAC 192k。
  loudnorm の文は `program-loudness.ts` の口（`loudnormMeasureFilter`・`loudnormLinearFilter`・`parseLoudnormJson`）を使い回す
  （書き出しの -14 の引数は前と同じ）。混ぜた音が測れなければ失敗にする（黙って元の音を使わない）。

### 5. Gemini

- **429**: 返答の頭 600 字の `retry in 48.3s` / `retry in 19h22m6s` の秒数 +2 秒待つ（無ければ 30 秒）。最大 4 回。
  待つのが 90 秒を超えるなら、待たずに「もう一度頼めるまで約 19 時間 22 分待つ必要があるため止めました」で止める。
  「retry in 500ms」「768.49ms」のミリ秒も読む（分と取り違えない）。
- **500 以上**: 2・5・10 秒待って 3 回（AnimalVideo には無かったが計画どおり入れた）。**1 回 180 秒で打ち切る**（打ち切りは送り直さない）。
  打ち切りは**本文の読みまで**含む（頭だけ返って本文が来ない応答で止まらない）。本文を読む途中の取り消しは「止めました」。
  失敗の応答の本文も読み切ってから送り直す。
- 読み上げ（ナレーションも）と Voice Design に効く。文字起こしは今まで通り。待つ口（`sleep`）と打ち切りの長さは差し替えられる。
- **作った声（`voice_…`）だけ `v1beta/interactions` で読む**。形は AnimalVideo（`tools/dub/gemini.py`）の実物から写し、
  `gemini-interactions.ts` の 1 ファイルに閉じた（`input[].content[].annotations` の `speech_metadata`、
  応答は `steps[]` の `model_output` の `audio` の最後の 1 つ）。応答に使った量が無いので、費用は音の長さ × 25 トークン/秒で見積もる
  （記録に `outputTokensEstimated: true`）。
- **既製の声は `generateContent` のまま**。送る本文は前と同じ（前からのテストがそのまま通る）。
- 計画の「`voice_…` を `generateContent` で読めるか 1 回だけ実際に呼んで確かめる」は、段 5a ではしなかった（実の Gemini は呼ばない指示）。
  AnimalVideo が interactions で読んでいるので、その形にした。
- **Voice Design**: `designVoice({ description, gender, displayName, languageCode: 'ja-JP' })` → `POST v1beta/voices`
  `{ store: true, voice: { model, type: 'prompted', display_name, gender, language_code, prompted: { input } } }` →
  `{ voiceId, sampleWav }`。`voice_` で始まらない ID は形が違うと失敗にする。試し聞きが無ければ null。
- 鍵はヘッダーだけ。エラーの文には鍵・原稿・返答の本文を入れない（AnimalVideo は本文の頭 600 字をエラーに入れているが、ixa の決まりに合わせた）。

## 段 5b の決め（Architect、5a のレビューで決めた）

1. **1.6 倍を超えたら止めるのは、3 通りの読み方をすべて試して、どれも 1.6 倍を超えたときだけ**。1 つでも収まればそれを使う。
2. **一致率は行ごとに、その行の消す範囲の中で比べる**（Shot 全体だと黙っている所で水増しされる）。
3. 記録の欄（`DubLineRecord`）は今の形でよい。段 5b で足してよい。
4. 2 人のセリフが 1 つの声の区間にまとまって行の区間が決まらないときは、どの行かを番号で言う日本語の理由で止める。
   段 5b の画面は、まとまった区間を文字数の比で行ごとに割った「行の区間」を各行に先に入れておく。

## 確かめたこと（段 5a）

- domain: 合成の dB の列で区間・つなぐ・捨てる・組・倍率の丸めと止め方・一致率・消す範囲・行の区間・読み方。
  上限・食い違いを破る値のテストを置き、検査を外すと落ちることを確かめた。
- media（実 ffmpeg）: 300Hz の元の声・3000Hz の環境音・500Hz の読み上げを合成し、消す範囲の中だけ元の声と環境音が消え、
  範囲の外は残り、読み上げが置いた時刻から鳴り、-16 LUFS ±0.5 になること。伸縮の長さ・切る長さ。
- Gemini: 偽の fetch で、429 の秒数の読み方・90 秒の境目・4 回まで・500 の 2/5/10 秒・打ち切り・interactions と voices の送る形と受け取る形。

## 決めたこと（段 5b）

### 1. 表（0058）

- `dub_jobs`（追記のみ）: Shot・元の Take・状態・出来た Take・費用・エラー（`suggestedSpans` つき）・記録。止めた行は作る側が上書きしない。
- `dub_jobs(shot_id)` に、待っている・動いている間だけの一意（同時に 2 回押されても 1 本。API は 409）。
- `tts_clips`: **ワークスペースごと**。(workspace_id, 鍵 = sha256(モデル・声・声のイメージ・行の読み方の指示・速さ・文)) に一意。
  保存は同じ鍵なら素材・長さ・額を書き替える（保存した素材が消された・読めないときに読み直して付け替える。付け替えないと毎回払う）。
  別のワークスペースの素材は指さない。素材の `origin` は `generated_dub`（最初に読んだジョブ）。
- `characters.dialogue_voice_profile_id`（声を消すと null）・`dialogue_level_db`（既定 0、-40〜12 dB）。
- `voice_profiles.designed_voice`（`{ description, gender, keyLabel }`）。試し聞きの素材の `origin` は `voice_design`。
- 鍵の名札は `GEMINI_KEY_LABEL`（秘密ではない設定値。`packages/config` の zod で英数字と `. _ -`、64 字まで）。

### 2. ジョブ（worker の `dub` キュー。同時 1）

1. 確かめる（読み直す行の話し手ごと）: セリフの声が無い／Gemini の声でない／作った声の名札が今の名札と違う → 止める。
2. 元の Take の動画を置き、音が無ければ止める。16kHz の RMS → 声の区間 → 行の区間（決まらなければ止め、
   まとまった区間を行の文字数の比で割った手の区間の案を `suggestedSpans` に入れる）。
3. 行ごとに順に（同時に頼まない）: 読み方を最大 3 通り。保存済みならそのまま使う。口に合わせる行は組ごとに伸縮して置き、
   伸縮した声の話している区間と元の声の区間を、**その行の消す範囲の中**で 10ms ごとに比べる。数が合い 0.9 以上で打ち切り。
   置く時刻・収める長さ・切る長さ・足す行は口に合わせない（一致率 null、収まった最初の読み方を使う）。
   **3 通りとも 1.6 倍を超えたときだけ止める。**
4. 音量: 行の区間の元の声（足す行は `levelLikeIndex` の行）と同じ大きさ + 距離（行の `levelDb`、無ければキャラクターの既定）。
5. 混ぜる（元の音がモノラルなら元の音も `pan=stereo|c0=c0|c1=c0` で写す。段 5a の不足を直した）→ -16 LUFS。
6. 書く直前に止められていないかを見て `recordTake`（spec・specHash・送った文・providerId・modelId・seed は元のまま、
   親は元の Take、理由 `dub`、`providerParams` は記録）→ 素材を測る口へ → 採用（**人が別の Take を選んでいたら奪わない**）→
   `shot.status` を流す → セリフの字幕を作り直す。
- 元の声のままの行は記録に `keep_original`（置いた時刻 = 元の区間）で残す（字幕の行の数を合わせる）。
- 止める理由はすべて「セリフの N 行目（話し手）: …」の日本語。知らない失敗は決まった文（「声を差し替える途中で止まりました。…」）
  だけを残し、元の文（パス・ffmpeg の出力）はログにだけ出す。
- **払った額は、読み上げを頼むたびに払った直後にジョブへ足す**（`addCost`。止めた行にも足す）。止めた・知らない失敗・
  キューの打ち切り・行の途中の失敗でも額を失わない。成功・失敗の書き込みは額を書かない。
- **出来た Take は必ず新しい Take**（`recordTake` の `onDuplicateMedia: 'new_take'`）。同じ中身の素材が既にあれば、その素材を指す
  新しい Take をこの Shot に作る（前の Take を返すと、見えなくした Take・別の Shot・複製で写した別の作品の Take を採用してしまった）。
- 採用は `selectTakeIfCurrent`（採用が元の Take のときだけ書く 1 回の UPDATE）。`selectTake` も同じ UPDATE の中でその Shot の Take かを確かめる。
- キューに打ち切られたジョブは失敗にする（他のキューと同じ）。

### 3. 字幕

`syncDialogueTelops` の `timingOf` は、採用 Take の `providerParams` が `dub` なら、記録の置いた時刻を行の順に話している区間として使う
（素材を測る前でも使う。差し替えた Take には必ず音がある）。消音した Shot・行の数が記録と違う Shot は今まで通り割り振る。

### 4. API

- `POST /shots/{id}/dub`（元は採用中の Take）→ 202。差し替えている最中・動画を作っている最中は 409、
  ほかの `dubBlocker` の理由（セリフが無い・採用 Take が無い・音が無い・全部元の声のまま）は 422。順番に入れ損ねたら失敗にしてから 500。
- `GET /shots/{id}/dub`（押せない理由と最後のジョブ）・`GET /dub-jobs/{id}`・`POST /dub-jobs/{id}/cancel`・
  `GET /projects/{id}/dubs/active`（MCP の `ixa_status` と jobs を省いた `wait` が数える）。
- キャラクターの PATCH に 2 欄。セリフの声は同じ作品の生きている声だけ（違えば 422）。作るときには受けない。
- `POST /characters/{id}/voices/design`（説明 1〜1000 字・性別・名前 40 字まで）→ 声を作った時点でそのキャラクターの声として保存
  （Gemini 側にも残るので、保存しないと作った声を失う）し、試し聞きを素材にして返す。口が無い（Gemini の声を使う設定・鍵・名札のどれか無し）
  なら 503、同じ名前は 409（Gemini を呼ぶ前）、Gemini が断れば 502、同じキャラクターで作っている最中は 429（この API の中だけの見張り）。
  名前の確かめの後に同じ名前が入って保存が一意で落ちたら、「（2）」〜を付けて保存し直す（**払った声を失わない**。駄目なら声の ID をログに残す）。
  試し聞きと同じ中身の素材が別の作品にあれば指さず、試し聞きは保存しない。
- `app.ts` は 800 行を超えていたので、書き出しフォルダの口の組み立てを `render-folder/mount.ts` へ移した。

### 5. 画面と MCP

- Shot のインスペクター「声の差し替え」: 「声を差し替える」（押せない理由はサーバの `dubBlocker` の文）・進み具合と取り消し・
  結果の表（行ごとの一致率 %・伸縮の幅・1.4 倍超は黄色の警告）。セリフの行の「差し替えの指定」（8 欄。domain の `DialogueDub` で確かめる）、
  行の区間で止まったら案を出して「案を入れる」。
- キャラクター: 「セリフの声」（その人の声から選ぶ）・「距離の既定（dB）」・「説明から声を作る」（説明・性別・名前 → 試し聞き →
  セリフの声にする）。前からの H3 向けの欄の見出しは「話し手の伝え方」にした（「セリフの声」を 2 つの意味で使わない）。
- MCP: `dub_takes`（`wait` の kind `dub`）・`edit_shots` の dialogue の `dub`・`edit_character` の 2 欄・`design_voice`。
  `dub_takes` と `design_voice` は課金なので危険度 costly。README の「会話劇の作り方」に差し替えの手順。

## 確かめたこと（段 5b）

レビューの直し（同じ中身の素材での Take の使い回し・読み上げの保存のワークスペースと消えた素材・払った額・知らない失敗の文・
二重に積む・声を作る口の同時押し）は、それぞれ先に落ちるテストを置いてから直した。0058 はどこにも当てていないので、その場で作り直し、
使い捨ての Postgres に当て直して db の全テスト（結合テストを含む）を通した。

- worker: 偽の読み上げと**実 ffmpeg** で、合成した音付きの動画を通しで差し替えた。新しい Take（系譜・spec・記録・-16 LUFS）、
  元の Take は変わらない、採用が移る、字幕が置いた時刻になる、2 回目は読み上げを頼まず費用 0。止め方（声が無い・名札が違う・
  3 通りとも 1.6 倍超で 3 回読む・行の区間と案・音が無い・止めたジョブ）。
- media: モノラルの元の音で声と元の声の大きさの差が 3.01 dB だったのを確かめてから直し、モノラル・ステレオとも 0.5 dB 以内。
- db: 使い捨ての Postgres に 0058 まで当て、読み上げの保存の一意と、セリフの声・作った声の名札の読み書き。
- API・MCP・画面: 保存と断り方（同じ作品の声だけ・距離の上限・409/422/503/409/502・入力の上限）。新しいテストは一度落ちることを確かめた。

## 行の区間を読み上げの長さで決める（段 5b の直し）

実の H3 の Take（6.58 秒、「ねえ、ネズミくん。」ネコ・「な、なんですか。」ネズミ）で止まった。声の区間は
(0.0, 0.15) クリック・(1.57, 2.45) 1 行目・(2.97, 3.69)+(3.76, 4.13) 2 行目・(4.86, 5.0)・(5.46, 6.03)・(6.07, 6.28) 環境音。
すき間の短い所からつないで行の数にそろえると、1 行目に頭のクリックが渡り、11.13 倍が要るとして止まった。
手の区間を入れると一致率 0.92 / 1.0 で通った。

- **文字起こしの語の時刻は使わない**。手元の faster-whisper small で試したが、この Take で 1 行目を 1.04〜4.76 秒と大きく外した
  （実際は 1.57〜2.45 秒）。区間の境目を決める用途には使えない。
- 代わりに**読み上げの長さ**を使う（どうせ読むので、保存して使い回せば余計に払わない）。worker は区間を決める前に、
  手の区間の無い読み直す行（元の声のまま・足す行でない行）の最初の読み方を読み、声の区間の長さの和を渡す。
- `assignByLength`（domain、純粋）: 行の順は変えず、1 行は続いた区間の並び（1 つ以上）を受け持つ。行の前・間・後ろの区間は
  飛ばしてよい（クリック・環境音）。費用 = Σ|log(元の声の長さ ÷ 読み上げの長さ)|（読み方のうち一番近いもの）
  + 飛ばした声 × 0.2/秒 + 行の中の途切れ × 0.5/秒（離れた区間をつながない）+ 0.25 秒未満の並び 1（読み上げも 0.25 秒未満なら無し）。
  動的計画法で一番良い割り当てと次の割り当てを求める（行の数 × 区間の数² で、Shot 1 つなら軽い）。
- 口に合わせる行は、どの読み方でも 0.8〜1.6 倍に収まらない並びを外れとする。外れの残る割り当てしか無ければ、
  その行だけ残りの読み方も読んで割り当て直し、それでも外れなら、どの行かを言う日本語の理由と手の区間の案（文字数の比）で止める
  （`lines_unassigned`。前は読み上げが長すぎる行は `too_fast` で止まっていたが、今はほとんど区間を決める時点で止まる）。
- 次の割り当てとの費用の差が 0.1 未満なら、良い方を使い、違う区間になった行の記録に `line_span_ambiguous` の警告を付ける。
- 置く時刻・収める長さ・切る長さの行も H3 は話しているので区間を受け持つ（消す範囲と音量合わせに要る）。倍率の範囲は求めない。
  元の声のままの行は読まないので長さを比べず、残りの区間を受け持つ。読み上げの長さが 1 つも無い並びは今まで通りつなぐ。
- 区間を決めるために読んだ読み上げは、ジョブの中で行ごとの読み直しに使い回す（保存の表を引く前に使う。同じ中身の素材が
  別のワークスペースにあって保存できなかったときも二重に払わない）。払った額は Take の額にも入れる。

確かめたこと: 上の実の区間の列（読み上げ 1.39 / 1.16 秒）で 1 行目 → (1.57, 2.45)、2 行目 → (2.97, 4.13)。頭がクリックだけ・
尻の環境音・3 行・間の行に手の区間・収まらない（どの行かを言う）・別の読み方なら収まる・迷いの警告。重み・外れ・迷いの幅を
それぞれ 0 にすると落ちるテストがあることを確かめた。worker は頭にクリックのある合成の音で通しを流し（前の割り当てでは落ちる）、
読み直しで同じ文を 2 回頼まないこと。

## 分かっている不足

- 行の区間は声の区間の並びを選ぶだけ。2 人のセリフが続けて 1 つの区間になると分けられない（手の区間を入れてもらう。案は文字数の比）。
- 読み上げの長さと元の声の長さは H3 の話す速さで食い違う。倍率の範囲の外（0.8 倍未満も）は割り当てられないので、
  H3 がとてもゆっくり話した行は、前は 0.8 倍に丸めて通っていたが、今は手の区間が要ることがある。
- 一致率は「話す／黙る」だけで、口の形までは見ない。
- 作った声は最後に使ってから 1 年で Gemini 側から消える。消えたときは読み上げの失敗（Gemini の理由）で止まる（専用の文は無い）。
- 作品の複製・取り込みでは、セリフの声は写さない（元の作品の声を指すため。距離の既定は写す）。写した先で選び直す。
- 差し替えのジョブの状態の出来事（`dub_job.status`）は無い。画面は 3 秒ごとに見直し、出来たら `shot.status` が流れる。
- 説明から作った声の保存は取り消しの記録に入れない（作り直しは課金のため）。
- 実の Gemini での確かめ（作った声を interactions で読めるか・CUT-01 の差し替え）は、取り込みの後に制作者の確認で行う。
