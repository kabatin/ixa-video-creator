# ADR-0042: MiniMax H3 を公式の書き方で頼み、試作と本番を分ける

## できあがり

- H3 への指示が**MiniMax 公式の書き方**になり、版で固定される（`h3-official-v1`）
- 生成の前に、**カメラの動きが決まっていない Shot** を名指しで言う
- vpipe の H3 が**試作・標準・本番の 3 段**になり、画面はモデル ID を書き写さずに段で選ぶ
- 採用した試作 Take を**「本番で作り直す」**。同じ指示・同じシード・同じ最初のフレームで、
  作る大きさだけ上げる。できた Take は試作の隣に積まれ、上書きしない

## Context

本制作の映像が、H3 の素の実力より明らかに悪かった。原因は 3 つあった。

1. **指示の書き方が自己流だった。** H3 は専用の書式（1 行目に `I2VA` などの種別、
   `integrated_multimodal_description`、`overall_soundscape`、`non_diegetic_music`）を前提に学習しており、
   素の文章を投げると寄りも動きも指示どおりにならない
2. **カメラの動きが未設定のまま作っていた。** 実測で、立ち上がる動きの Shot が
   **立ち上がった瞬間に顔が画面の外へ出る**（カメラが追わないため）
3. **常に 832×480 で作っていた。** H3 の学習解像度は 1344×768 で、試作の解像度のまま仕上げていた

## Decision

### 1. 指示は公式の書式へ組み立て直し、版で固定する

`packages/providers/video/src/vpipe/h3-prompt.ts` が組み立てる。版（`H3_PROMPT_FORMAT`）を持ち、
golden test で文面を固定する。**書式を変えたら版を上げる**（同じ仕様から違う映像が出ることを、
黙って起こさない。ADR-0003 の再現性）。

### 2. カメラの動きが未設定なら、生成の前に言う

`lacksCameraMovement`（domain）。**`static`（止める）は決定であって未設定ではない。**
`null` のときだけ数える。止める／止めないを区別せずに警告すると、決めた人に毎回警告が出る。

### 3. 段はモデルの宣言が持つ（`qualityTier`）

`draft` / `standard` / `final` を `VideoModelDescriptor` に持たせ、`/models` で返す。
**画面はモデル ID を書き写さない。** 「同じ Provider の、段が `final` のモデル」を一覧から引く
（`finalTierModelOf`。domain）。元のモデルが段を宣言していなければ作り直さない
（段を持たないモデルは、同じ Provider の本番と同じ系列とは限らない）。

### 4. 「本番で作り直す」は、仕様を変えずに段だけ変える

- 同じ指示・**同じシード**・同じ最初のフレーム。変えるのは生成の大きさだけ
- **Take は追記のみ。** できた本番は試作の隣に積まれる（ADR-0003）
- 系譜を残す（`parent_take_id` / `regeneration_reason`）。**作る瞬間にしか親を持てない**
- まとめて積む口もある（`POST /projects/{id}/shots/bulk/remake-final`）。`dryRun` で
  押す前に本数・見込み・飛ばす理由を出す

## 実測（M5 / 32GB・vpipe-api）

| | 試作 | 本番 |
|---|---|---|
| 生成の大きさ | 832×480 | **1344×768** |
| 2.67 秒の Shot | 305 秒 | **842 秒** |
| 尺 1 秒あたりの目安 | 90 秒 | **256 秒** |

## Consequences

- **同じシードでも、大きさが変われば絵は変わる。** 「試作をそのまま高画質にする」のではなく
  「同じ指示で撮り直す」。構図も表情も変わりうる。これを嫌う場合のために ADR-0044 がある
- シードは **`generation_jobs` の行に積む**。worker は行だけから仕様を組み直すので、
  積み忘れると `specHash` が食い違って `spec_drift` で落ちる（実際に 1 本目で落ちた。L-012 と同じ形）
- 本番の段は vpipe-api が `quality: "final"` に対応している必要がある。
  対応していない環境では、画面が押せない状態で理由を出す
