# ADR-0032: 使う AI を、この環境で見つかったものから用途ごとに選ぶ（と、入力を AI が手伝う）

Status: Accepted（1〜4 段目。Gemini は廃止で対応しない）
Date: 2026-09-30
Decider: Claude（Architect）。制作者の判断（2026-09-30「初回起動時には端末にインストールされている AI をリスト表示した上で
選択して設定出来るようにしたい。テキスト系、画像生成系、動画生成系をそれぞれ選べるといい」「動画生成には PR #4 のローカル生成も加えたい」）

## Context

- どの AI を使うかは、起動時の環境変数で固定だった（`STORYBOARD_DRAFTER`・`IMAGE_PROVIDER`・`VIDEO_PROVIDER`・`LOCAL_VIDEO_GENERATOR`）。
  入っているかを確かめる処理は無く、変えるには `.env` を書いて起動し直すしかなかった
- この Mac には claude 2.1.283・codex 0.154.0・gemini 0.25.1・grok 0.2.102 が入っていた。テキストの口は Claude だけ、画像は Codex だけ
- API には fal が登録されておらず（worker にはあった）、AUTO も一覧も fal を知らなかった
- この API は無認証で、LAN に出すことがある

## Decision

### 選択は DB に 1 行（`ai_settings`）

この環境に 1 行（id は `default` だけ。check 制約）。入っている AI は API と worker が動く機械のものなので、
ワークスペースや Project ではなく環境に持つ。**使うたびに読む**（選び直したら次の 1 回から効く）。

行が無い間は「まだ選んでいない」で、初期値は今までどおりに動く形にする。テキストと画像は環境変数のまま。
**動画はお試し**（今までの AUTO は、fal を有効にしても API に登録されておらず、vpipe は AUTO に出ないので、お試しを選んでいた）。
知らない AI の名前が残っていたら「まだ選んでいない」に戻す（読み込みで落とすと全部使えなくなる）。

### 見つけ方（`GET /ai/tools`）

- CLI: 決まった名前（claude・codex・gemini・grok）だけ `--version` を 5 秒で叩く。入っていない・時間切れ・起動できないを分けて言う
- 手元の生成サーバ（vpipe-api、ADR-0031）: `GET /v1/health` を 2 秒で。何も積まない
- fal: キーの有無だけ見る（値は見ない）
- 何に使えるかは domain の表 `AI_TOOLS` に 1 か所。**口（アダプタ）がある用途だけ**を書く。選べるかの規則は `aiChoiceProblem` の 1 か所で、
  一覧の「選べない理由」と保存の 422 が同じ文を言う
- 初めての組み合わせを勧める: テキストは Claude → Codex → Gemini → Grok、画像は Codex、動画は vpipe → 静止画を動かす。**お金が掛かるものは勧めない**

### お金が掛かる口と手元のサーバは `.env` で有効にしてから選べる

fal は `VIDEO_PROVIDER=fal` とキー、vpipe は `LOCAL_VIDEO_GENERATOR=vpipe` のときだけ登録し、選べる。
**画面の選択だけで有料の口を開けない**（無認証の API に LAN から届くことがあるため）。vpipe は、入れていない人の一覧に出さないため（ADR-0031 のまま）。
API にも fal を worker と同じ条件で登録した。

### 選んだ AI を使う所

- 絵コンテの案: 押すたびに、いま選んでいるテキストの AI の口で
- Shot の絵: API がいま選んでいる画像の AI をジョブに記し、**worker はジョブに記された口で作る**（起動時の設定で選ばない。無い口は理由を付けて失敗）
- 動画: **AUTO は選んだ動画の AI のモデルの中から選ぶ**（API の 1 件・一括、worker の自動の作り直し）。人が選んだ AI なので、
  ふだん AUTO に出ない印（`routable: false`）のモデルも候補にする。明示したモデルはそのまま使える

### 画面

初めてワークベンチを開いたときに「使う AI」を 1 度だけ出す（選ばずに閉じても次からは出さない）。あとはメニュー「iXA Video Creator > 使う AI…」。
用途ごとに、使える AI（選べないものは理由つき）と、入っているがその用途には使えない AI の名前を 1 行で。API キーは扱わない（規約 6）。

## やらないこと（今回の 1 段目）

- Project ごとの選択、画面での API キー入力
- Gemini・Grok のテキストの口、Codex のテキストの口（2 段目・4 段目）
- 入力の AI 補助（3 段目）

## Consequences

- 実機で 4 つの CLI が版つきで見つかり、fal は「.env で有効に」、vpipe は「.env で有効に」と理由が出た。検出は 4〜5 秒
- 確かめる途中で、前からあった不具合が 2 つ見つかった
  - CORS が PUT を許しておらず、ブラウザからの PUT（最初のフレームを手で付ける、ADR-0025）が止まっていた
  - medium のダイアログ（環境設定・変更履歴・新規 Shot など）が WebKit で 2px に潰れていた（高さ auto の枠で h-full）

## 追記（2026-10-02）: 自動レビューの vision 判定もテキストの AI で選ぶ

制作者 2026-10-01「自動レビューの繋ぎ」。テキストの AI が Claude なら画像を見る Claude のレビュー、それ以外はお試し（スタブ）。
生成と同じく **worker が判定するたびに選択を読む**。Codex・Gemini・Grok はまだ判定に使えない。Claude は契約の利用枠を使う。

## 追記（2026-10-02）: 2〜4 段目。テキストを Codex・Grok にも広げ、入力を AI が手伝う

- **テキストの AI は Claude・Codex・Grok。** CLI ごとの違い（引数・返事の取り出し方・サインイン前の言い方）は
  `provider-llm/text-cli.ts` に閉じた。どれも使い捨ての作業場所で呼ぶ（リポジトリの設定を読ませない）。
  Codex は `exec --sandbox read-only` で最後の返事をファイルから、Grok は `-p --output-format plain` の標準出力。額が測れない CLI は 0
- **Gemini CLI は廃止されたので対応しない**（制作者 2026-10-02）。入っていても「使えない」と出す
- 絵コンテの案も 3 つのどれでも作れる（プロンプトと確かめ方は Claude と同じ。`text-cli-drafter.ts`）
- **入力を AI が手伝う（3 段目）**: 8 欄（コンセプト・ルック・避けたいもの・Shot の説明・雰囲気・識別アンカー・衣装・ロケーションの説明）の
  下の「✦ AI」で、注文（任意）を添えて案を 1 つ出す。**「使う」を押すまで欄は変わらない**（使えばいつもどおり保存し ↺ で戻せる）。
  空の欄は材料から考え、書いてあれば意図を残して整える。欄ごとの使われ方は domain の `ASSIST_FIELDS`、材料は API の `assist-context.ts`
- この Mac では Grok にまだサインインしていない（使うと「サインインしていません」と理由が出る）。実際の返事は Claude と Codex で確かめた
- 自動レビューの画像の判定は Claude だけ（Codex・Grok を選んでいるときはお試し）
